# Claude Code 設計模式手冊

從 Claude Code v2.1.88 原始碼裡提取的 AI 系統設計模式。
給 AI 工具的重度使用者和 AI 系統的建造者 — 你不需要會寫程式，但你需要對「AI 系統是怎麼設計的」有好奇心。

邊做邊學 — 每一章你做完就能用，不需要讀完全部才開始。

## 章節

| 章 | 你在做什麼 | 做完後你會有什麼 |
|----|-----------|----------------|
| [第 1 章](01-設好你的第一個系統.md) | 從零設好一個能用的 AI 系統 | 可運作的 CLAUDE.md + 工具定義 + 權限設定 |
| [第 2 章](02-用了一週開始調整.md) | 用了一週，開始調整 | 修正壞習慣的方法 + 省 token 的策略 |
| [第 3 章](03-讓AI記住你.md) | 讓 AI 記住跨對話的東西 | 分類記憶 + 召回機制 + 記憶維護 |
| [第 4 章](04-跑順了開始自動化.md) | 跑順了，開始自動化 | Hook 自動化 + Skill 可重用指令 |
| [第 5 章](05-讓別人也能用.md) | 讓別人也能用 | 可交接的系統 + 跨領域搬遷的方法 |

## 三層學習

每一章有三層，你可以根據需要停在任何一層：

1. **照著做** — 跟著步驟做完，就有一個能跑的系統
2. **理解為什麼** — 每個決策點的「為什麼這樣選」，讓你知道設計背後的原因
3. **挑戰它** — 每章結尾的「想一想」段落，拿 [OpenHarness](https://github.com/HKUDS/OpenHarness)（香港大學用 Python 重寫的 Claude Code）跟原版比較。同一個問題、兩個不同的選擇 — 讀完你會知道在你的情境下哪個更好

## 怎麼讀

**第 1 章是基礎，建議先做。** 後面的章節會引用第 1 章的概念（分層設定、組裝式指令）。第 2-5 章可以跳著看，但如果碰到不懂的東西，回第 1 章找。

每個「決策點」的結構：
1. **你在做什麼** — 當前的任務
2. **你碰到的決策** — 要選 A 還是 B
3. **原始碼怎麼做的** — Claude Code 的選擇，附程式碼片段和行號
4. **為什麼這樣選** — 設計背後的原因
5. **你現在做這件事** — 具體的行動
6. **出問題了？** — 常見症狀和排錯方向

每步有兩條路線：**🅰 用 Claude Code** 和 **🅱 建自己的 agent**。挑你需要的那條。

## 全景速查表

五章共 15 個設計模式。碰到問題時來這裡查：

| 你碰到什麼 | 用哪個模式 | 在哪 |
|-----------|-----------|------|
| 指令太多太亂 | 分層設定覆蓋 | 第 1 章 |
| Prompt 越改越長 | 組裝式指令 | 第 1 章 |
| AI 用錯工具 | 工具自帶說明書 | 第 1 章 |
| 權限太鬆或太緊 | 信任階梯 + 斷路器 | 第 1 章 |
| AI 有壞習慣 | 結構化行為規則 | 第 2 章 |
| Token 太貴 | 靜態/動態邊界快取 | 第 2 章 |
| 長對話忘東西 | 有損壓縮 + 完整備份 | 第 2 章 |
| AI 不記得你是誰 | 分類記憶 | 第 3 章 |
| 舊記憶被當事實 | 記憶保鮮 | 第 3 章 |
| 記憶太多載入太慢 | 按需召回 | 第 3 章 |
| 重複操作要手動觸發 | 事件驅動 Hook | 第 4 章 |
| 常用流程要重新解釋 | 懶載入 Skill | 第 4 章 |
| 共用 vs 私人設定混在一起 | 雙軌設定 | 第 5 章 |
| 模組搬到新專案就壞 | 零依賴模組 | 第 5 章 |
| 不同環境行為不一致 | 環境自動偵測 | 第 5 章 |
